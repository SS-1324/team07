# DIAMONDATA 프론트엔드 작업 공유 · Modern v2

작성일: 2026-11-18. GitHub 업로드 상태: 브랜치 생성이 연결 권한 오류(403)로 거절되어 아직 커밋·PR 없음. 아래 실행 방법은 업로드 후 기준이며 현재는 전달 ZIP을 풀어 바로 확인할 수 있습니다.

구현 상태: **디자인·상호작용 미리보기 구현 / 기존 PHP 화면 통합 대기**.

## 디자인 2차 개선

밝은 사이드 메뉴와 넓은 여백, 네이비·그린 계열의 색상, 큰 숫자와 정돈된 표, 메인 화면의 실사 느낌 야구장 배너를 적용했습니다. 야구장 이미지는 AI로 생성한 가상 경기장으로 실제 구단·구장 사진이 아닙니다. assets/stadium.webp에 포함하고 index.html에도 내장하여 인터넷 없이 표시됩니다. 기존 조회·비교 기능 및 데이터는 유지했습니다.

새 디자인은 assets/modern.css에서 수정합니다. 메인 배너는 구단 비교 화면에만 표시되어 다른 분석 화면에서 공간을 차지하지 않습니다. GitHub 쓰기 권한 문제는 해결되지 않았으므로 이번 디자인도 ZIP으로 공유하는 상태입니다.

## 팀원이 바로 확인하는 방법

1. 이 문서가 포함된 PR의 작업 브랜치를 선택하고 GitHub의 Code → Download ZIP으로 내려받습니다. 이미 clone한 경우 해당 브랜치로 전환해도 됩니다.
2. 압축을 푼 뒤 `docs/frontend-preview/index.html`을 Chrome 또는 Edge로 엽니다. Apache, DB, npm 설치 없이 동작합니다.
3. KBO/MLB 전환 → 선수 검색 → 이름 클릭 → 계약과 성적 그래프 → 별 2개 선택 → 관심 선수 → 2명 체크 → 비교 순서로 확인합니다.
4. 의견은 PR에 화면 이름, 선택한 리그/시즌, 기대 동작을 적어 남깁니다.

GitHub 파일 페이지에서는 HTML 소스가 보입니다. 파일을 내려받아 열어야 하며 공개 웹사이트로 배포한 상태는 아닙니다.

## 구현한 화면과 동작

| 화면 | 구현 내용 |
|---|---|
| 공통 화면 | 어두운 사이드 메뉴, 청록색 강조, 리그/시즌 필터, 화면 폭에 따른 배치 변경 |
| 구단 종합 비교 | 지출·성적 표, 상위 구단 막대, FA 지출과 승률 산점도, 구단별 계약 이동 |
| 선수 검색·상세 | 검색/기록 종류 필터, 시즌 기록, 계약기간 강조 그래프, 지표 선택 |
| FA 계약 | 시즌 유효 계약, 총액/AAV, 등록·수정 입력 화면과 연도·금액 검증 |
| 분석 | 구단/기간 집계, 구단×기간 집계, 구단·시즌 소계와 드릴다운, MLB 시즌 효율 순위, 성적 추이 |
| 관심 선수 | 별 선택, 2~4명 같은 시즌 성적 비교 |
| 공통 상태 | 빈 결과, 로딩·오류 재시도, 페이지 이동, CSV 다운로드, 모달 |

등록·수정의 실제 저장 버튼은 비활성화되어 있습니다. 삭제·선수 정보 수정 화면 및 실제 DB 쓰기 연결은 이번 공유본에 포함되지 않습니다. 관심 선택은 메모리에만 유지되므로 새로고침하면 초기화됩니다.

## 어떻게 구현했는가

기존 DIAMONDATA 가안의 디자인 방향을 유지하면서 공유 SQL의 실제 구단·선수·계약 데이터로 화면을 구성했습니다. HTML은 구조, CSS는 배치·스타일, JavaScript는 화면 상태와 사용자 동작을 담당합니다. AI를 활용해 코드와 설명 문서를 작성하고 상호작용을 자동 검증했습니다.

- `frontend-preview/shell.html`: 메뉴, 필터, 결과 영역, 모달의 공통 구조.
- `frontend-preview/assets/style.css`: 반응형 스타일.
- `frontend-preview/assets/app.js`: 표·그래프 출력, 탐색, 비교, 입력 검증.
- `frontend-preview/assets/preview-data.js`: 미리보기 전용 조회·계산.
- `frontend-preview/assets/snapshot.js`: 공유 SQL에서 추출한 고정 데이터.
- `frontend-preview/build.py`: 위 소스를 하나의 `index.html`로 묶는 도구.
- `frontend-preview/tests/interactions.cjs`: 화면 동작 회귀 테스트.

소스 수정 후 저장소 루트에서 `python3 docs/frontend-preview/build.py`를 실행하고 생성된 `index.html`도 함께 커밋합니다. 확인만 할 때는 Python도 필요 없습니다.

## 데이터 출처와 해석

스냅샷은 노션의 2026-11-16 공유 SQL에서 추출했습니다. 2026-11-18 확인한 GitHub main 커밋 `7175ac22788cad0a66a3084495b5159347ee314d`의 `database/dbcreate.sql`, `database/dbinsert.sql`과 원본 파일의 Git blob SHA가 일치합니다.

- dbcreate.sql: `3f9fce031c1542054939030db74abd51459fe6ba`
- dbinsert.sql: `73e27bac19a70db4003afe750717616ed9466548`
- 구단 41행, 선수 258행, 구단 시즌 479행, 선수 시즌 1,975행, 계약 291행.
- 노션이나 GitHub DB 파일의 후속 변경은 이 미리보기에 자동 반영되지 않습니다.
- KBO WAR·생년월일·세부 포지션 누락은 임의로 채우지 않았습니다. KBO에서는 OPS/ERA 등을 표시합니다.
- KRW 원본은 만원, USD 원본은 달러이며 화면은 억 원/$M으로 환산합니다. CSV는 원본 저장 단위입니다.
- AAV 합계는 실제 시즌 현금 지급액이나 구단 전체 연봉 총액과 다릅니다.

## 기존 백엔드에 연결할 때

기준 문서는 [BACKEND_API.md](BACKEND_API.md)입니다. 이번 PR은 미리보기와 문서만 추가하며 기존 `pages/`, `layout/`, `assets/`, `backend/`, `actions/`, DB 및 원래 prototype은 변경하지 않습니다.

앞서 별도로 작성했던 PHP JSON 어댑터는 현재 팀 백엔드와 계산이 중복되므로 이번 PR의 서비스 코드에 넣지 않았습니다. 실제 서비스에는 팀원이 만든 함수를 사용해 `pages/`, `layout/`, `assets/`로 UI를 통합해야 합니다. 미리보기의 브라우저 계산을 과제의 SQL 분석 구현으로 제출하면 안 됩니다.

| 연결 대상 | 현재 미리보기와 맞춰야 할 점 |
|---|---|
| `team_seasons_list()` | 현재 서버의 반환 키에 구단 표/차트를 연결 |
| `players_search()`, `player_seasons()`, `player_contracts()` | 서버 검색은 현재 소속 기준, 미리보기 표는 선택 시즌·구단·stint 기록 기준. 검색과 상세의 범위를 구분 |
| `contracts_list()`, `contract_find()` | 기존 정렬·필터·통화 규칙으로 조회 |
| `players_by_ids()`, `players_compare()` | 서버 비교는 계약 전 최대 2시즌/계약기간 기준. 현재 미리보기의 같은 시즌 비교와 구분 |
| `analysis_aggregate()` | 1~3개 복합 그룹 선택, 연도 범위, 역할 및 반환 지표에 맞춰 확장 |
| `analysis_rollup()`, `analysis_drill_contracts()` | 리그/구단/연도 단계와 소계 구분을 서버 `row_level`에 연결 |
| `analysis_ranking()` | 서버는 계약기간 지급액÷WAR 및 OPS/ERA 순위 지원. 현재 미리보기의 선택 시즌 AAV÷WAR와 다름. KBO 순위도 서버 OPS/ERA 기준으로 구현 필요 |
| `analysis_window()` | 서버의 연도별 통합 기록·나이·리그 평균·순위 및 이동평균 결과로 그래프 연결 |
| `actions/*`, 세션 | POST 폼의 `csrf_field()`, 기존 필드 이름, 실패 시 입력 복원, 관심 목록 PHP 세션 적용 |

화면 출력은 `h()`, 주소는 `url()`, 금액은 `format_money()`를 사용하고 SQL은 `backend/queries/`에 둡니다. 담당 이름은 실제 담당자가 통합 파일 주석에 적습니다.
